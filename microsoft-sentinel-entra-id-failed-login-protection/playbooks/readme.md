# Entra Failed Login Response Playbook

## Overview

This Microsoft Sentinel playbook automates the initial handling of incidents generated by the Entra ID failed sign-in detection rule.

The playbook is implemented using Azure Logic Apps and integrates with Microsoft Sentinel to receive incident information and initiate an investigation workflow.

The initial implementation focuses on incident ingestion and auditability. It does not automatically disable user accounts or modify authentication settings.

## Architecture

The playbook operates as part of the following security workflow:

1. Microsoft Entra ID records authentication events.
2. Microsoft Sentinel collects sign-in logs.
3. A scheduled analytics rule identifies repeated failed sign-in attempts.
4. Sentinel creates an incident.
5. An automation rule invokes this playbook.
6. The Logic App receives and processes the incident payload.

## Workflow

### 1. Incident trigger

The Logic App uses the Microsoft Sentinel incident trigger.

The workflow starts when Sentinel invokes the playbook with an incident payload.

### 2. Incident payload capture

The initial implementation uses a Compose action to capture the incoming incident payload.

This provides visibility into the incident data available to subsequent workflow actions.

### 3. Future investigation capabilities

The workflow is designed to support additional investigation and response capabilities, including:

- Extracting affected user accounts.
- Retrieving user information through Microsoft Graph.
- Collecting authentication and sign-in context.
- Enriching incidents with source IP and application information.
- Generating investigation summaries.
- Sending notifications to security administrators.
- Supporting controlled account containment when compromise is confirmed.

These capabilities are planned extensions and are not enabled in the initial implementation.

## Deployment

### Prerequisites

- An Azure subscription.
- A Microsoft Sentinel-enabled Log Analytics workspace.
- Microsoft Entra ID sign-in log integration.
- Permission to create and manage Azure Logic Apps.
- Permission to configure Microsoft Sentinel automation rules.
- Appropriate permissions for the Sentinel connector and managed identity.

### Deployment template

The directory contains:

`azuredeploytemplate.json`

This template provides the initial Logic App deployment structure.

Deployment-specific parameters, connector configuration, and managed identity permissions must be validated and configured for the target Azure environment.

### Integration with Microsoft Sentinel

After deploying and configuring the Logic App:

1. Open Microsoft Sentinel.
2. Navigate to Automation.
3. Create or edit the relevant automation rule.
4. Configure the incident-created trigger.
5. Add the deployed Logic App as the playbook action.
6. Verify that the automation rule references the correct subscription, resource group, and Logic App.

## Security Considerations

- Use managed identity where supported instead of embedding credentials.
- Apply least-privilege permissions to the Logic App identity.
- Avoid storing passwords, access tokens, or other secrets in workflow definitions.
- Restrict access to Logic App run history because incident payloads may contain sensitive information.
- Do not automatically disable accounts based solely on failed sign-in counts.
- Require additional investigation or an explicit response policy before containment actions are executed.

## Testing and Validation

Before enabling the playbook in a production environment:

- Validate the ARM template.
- Verify the Sentinel connector configuration.
- Confirm managed identity permissions.
- Generate a controlled test incident.
- Confirm that the Logic App receives the incident payload.
- Inspect workflow execution history.
- Verify that no unauthorized account modifications occur.

## Limitations

The initial implementation provides incident ingestion and payload capture only.

It does not currently implement:

- Microsoft Graph user enrichment.
- Automated notifications.
- IP reputation analysis.
- Automated account disabling.
- Automated account restoration.

These capabilities are intended for future development.
